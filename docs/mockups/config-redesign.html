Design review · 25 October 2026

Make the next step obvious.

A guided first setup, followed by a simple workspace for everyday use.

Scope: a redesign concept based on your supplied configuration screenshot. These are heuristic observations, not findings from user testing. The existing extension is unchanged.

What gets in the way today

  1. The data format leads the experience. “CSV group” and “Indexed accounts” describe implementation. A new user first needs to know which website they are setting up.
  2. Too many decisions arrive together. Renaming, creating a group, selecting a file, entering a domain, and choosing replacement rules share one screen.
  3. Progress is incomplete. “Step 1 of 2” describes importing, while “Login page setup” is elsewhere. Users cannot tell how much setup remains.
  4. Some labels promise the wrong thing. “Verify accounts” can sound like checking whether passwords work. “Review import” says what happens next.
  5. Completion is vague. “Done” does not explain whether setup is saved, fields are ready, or any website is authorized.

What this concept changes

  1. Website → Accounts → Login fields. One task per step; persistent progress and a visible setup summary.
  2. A workspace is the user’s mental model. Name it after the application or environment. CSV is a file format, not the navigation.
  3. Consequences come before confirmation. Show what is added, updated, kept, or removed. Keep replacement behind an explicit choice.
  4. Detection leads; manual setup remains available. Show permission in context, a field result, and a demo check before the ready state.
  5. Setup ends with a next action. Explain how to open the extension, choose an account, and fill. The user still submits manually.

Try these tasks with a new user

  1. First-time setup: “Set up Acme staging and add the sample accounts.” Observe whether they can finish without help.
  2. Everyday update: choose Existing workspace above. “Add the new file, but keep accounts missing from it.” Ask them to predict the result before confirming.
  3. Error recovery: choose Import with an error. “Explain what is wrong and decide how to continue.” Record whether they understand that one record will be skipped.
  4. Readiness: “Where will these accounts work, and what do you do next?” Look for confusion between saving setup, filling fields, and submitting a login form.

What still needs validation

“Workspace” is a proposed UI label for the existing group concept; confirm that it fits your team’s vocabulary. This mock shows one website per setup; additional domains and multiple groups still need a production design pass. Keyboard focus, labeled inputs, responsive layout, and visible error recovery are implemented here, but the screenshot alone cannot establish the accessibility of the existing page.

Imports, browser permissions, field detection, and test results are simulated. This page does not parse account files, read credentials, communicate with the extension, or store data. No success state proves real-site compatibility.
